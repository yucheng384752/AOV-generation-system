# Goal

發布 1.1.1：每個 node 下方以單一接點建立虛線返回線，保留左右正向連線，並縮減定義完整性的必填欄位。

# Success Criteria

- 每個 node 下方只有一個可作為返回起點或終點的接點。
- 返回模式可在一般 node 間拖曳並新增虛線；正向模式維持左入右出。
- 說明性欄位可留空，不再讓文件維持草稿。
- 版本規則被記錄；測試與正式建置通過。

# Current Context

從 `origin/dev` 建立 `fix/1.1.1-return-handles`。JSON 檔案契約未改變，因此應用程式版本改為 1.1.1，schemaVersion 維持 1.1。

# Codex Notes

- React Flow 使用 loose connection mode，單一下方 handle 同時接受拖出與拖入。
- handle ID 區分 forward/return 並做 URL 編碼，避免 React Flow 內部 CSS selector 因 JSON 引號失效。
- 新返回線以來源第一個 output 與目標第一個 input 保存契約；既有返回線保留原 port ID，但一律顯示於單一下方接點。
- 必填保留：專案／節點／連接埠名稱、外部引用名稱與位置、返回原因，以及重複 Loop 的安全設定。
- 改為選填：專案目的、業務／function／buffer／port 說明、資料欄位、輸出與連線條件、欄位映射。
- 版本規則加入 AGENTS.md：第一碼為核心方向、第二碼為中等功能、第三碼為小功能或修正；同次取最高層級。

# Review Findings

- 最初使用原始 JSON 作為 handle ID，React Flow 組合 CSS selector 時因引號失敗；改為 encodeURIComponent 後解決根因。
- 每個節點原本依輸入／輸出數量顯示多個返回點，不符合使用者預期；已改為單點。

- 實際 Chromium：兩個一般 node 各一個底部接點；B → A 拖曳成功；返回 edge 數量由 0 變 1；strokeDasharray 為 `7px, 5px`；接點中心位於節點底邊。

# Decisions

- Accepted（使用者）：每個 node 下方只顯示一個返回點。
- Accepted（使用者）：說明可移除必填，只保留結構與安全必要欄位。
- Deferred：依具名 port 選擇返回契約。單點介面先使用第一組 output/input；需要多契約選擇時再於連線設定面板加入選擇器。
