## 1. 系統定位與範圍

本專案是 AOV 架構與流程定義工具，使用多節點有向圖描述系統的 dataflow 與 workflow，並產生 Agent 可理解、修改及重新匯入的描述檔案。

**本系統只做定義，不做所描述功能的實作或執行。**

- 節點中的 function 用於描述功能目的、輸入、輸出、處理規則、參數與變數。
- 系統不依節點定義產生功能實作、不執行程式碼、不呼叫節點所描述的 API，也不處理實際業務資料。
- 返回原因、條件與 loop 設定均為架構語意；系統不求值條件、不排程流程、不執行迴圈或重試。
- Agent 可讀取與修改描述檔；後續功能實作由外部開發流程負責，不屬於本系統範圍。
- 編輯器本身仍須實作畫布操作、節點設定、儲存、匯入匯出及描述資料驗證。
- 格式與圖結構驗證不等於執行功能，也不保證所描述業務邏輯正確。

## 2. AOV 與節點

- AOV 是可描述系統 dataflow 與 workflow 的多節點有向圖。
- 一般節點是功能描述的最小單位，可向下延伸子 AOV 與孫 AOV。
- 每個節點可獨立設定 function 的功能、變數與參數。
- 一個節點只描述一個 function，包含名稱、用途、處理步驟、規則與錯誤處理；功能內部細節使用子 AOV 拆解。
- 輸入、輸出、參數與變數提供欄位表單，設定名稱、型別、必填與說明；參數另有預設值。支援物件與陣列，並提供進階 JSON Schema 編輯。
- 一般節點最多接受一條正向輸入線；多來源輸入須先經過緩衝節點。
- 緩衝節點可描述倉儲及多參數輸入，允許多個上游來源。
- 緩衝節點可新增具名輸入，每個輸入最多連接一條正向線；模式包含「等待全部」「任一到達」「保留最新」「倉儲」，並可填寫整合或讀寫規則。模式僅描述、不執行。
- 節點可有多個輸出，透過箭頭連接下游節點。

## 3. 連線與 loop

- 正向連線禁止形成循環；新增、修改連線與匯入時均須驗證。
- 返回線以虛線顯示，不計入一般節點的正向輸入數量。
- 返回線可串接中間處理節點；起點與終點接在下方，中間節點右進左出，各段仍是獨立、可定義的 return edge。
- 每條返回線必須描述返回原因。
- loop 須有獨立且明確的設定，不能只靠圖形循環推斷其語意。
- loop 設定於返回線上，每條返回線必填返回原因與觸發條件。
- 模式包含「單次返回」「固定次數」「條件式重複」；重複模式須描述次數上限及達上限後的處理，條件式重複另須描述停止條件。

### 子 AOV 邊界

- 每張子圖專屬於一個父節點，以獨立畫布開啟，不由多個父節點共用。
- 父節點的輸入與輸出透過子圖明確的邊界入口、出口對應，禁止直接跨圖拉線。
- 子圖入口可分送至多個內部節點；多來源合併仍須經緩衝節點。
- 子孫層級沿用相同規則，禁止祖先引用循環。

## 4. 畫布與操作

- 使用 React Flow 建立可拖曳節點、可新增箭頭的畫布。
- 畫布位於中央並占最大面積。
- 下方工具列以圖示清單呈現：一般節點、緩衝節點、虛線返回箭頭；hover 顯示工具說明，並提供鍵盤可用的說明方式。
- 右上方提供四個按鈕：儲存、匯入、匯出、清除。
- 儲存包含「另存新檔」與「暫存畫布」。
- 匯入與匯出使用單一的本地描述檔案。
- 清除的範圍是目前畫布上的所有 items，即目前圖的節點與連線；不是全專案清除。
- 清除前必須顯示「是否清除整個畫布」確認彈窗。
- 刪除父節點或清除目前畫布時，連帶刪除受影響節點所屬的全部子孫圖。
- 確認彈窗須列出受影響的節點、連線及子孫圖數量，並提供操作後復原能力。
- 清除目前圖保留該圖本身、其父節點與其他不受影響的畫布；不刪除父節點對目前圖的引用。

## 5. 儲存與描述檔

- 支援專案 AOV 圖長期保存。
- 可輸出 Agent 可理解與修改的檔案架構。
- 採用單一版本化 `.aov.json` 描述檔，格式版本為 `1.0`；領域語意與畫面布局分區，保留穩定 ID。
- 描述檔須能表達節點、連線、功能定義、返回原因、loop 與子 AOV 關係。
- 匯入資料必須先完成格式與關聯驗證，成功後才替換目前資料；失敗時保留原畫布並提供可修正的錯誤訊息。
- 瀏覽器自動暫存完整專案，含全部子圖，也提供手動暫存；下次開啟恢复草稿。
- 本地完整檔作為長期保存依據；另存新檔與匯出使用同一格式，包含全部子圖與布局。儲存位置由瀏覽器下載設定決定。
- 匯入在驗證完成後提示取代範圍與未輸出變更，使用者確認才取代；不支援版本拒絕載入。
- JSON Schema 是資料契約的唯一來源；表單以局部修改保留進階欄位，複合結構改用進階編輯，不降級或丟棄限制。
- 定義未完成仍可暫存與匯出草稿；「檢查定義」顯示可定位的缺漏。循環、失效引用等結構錯誤阻擋匯入／匯出。
- 檢查通過只表示定義完整，不宣稱業務邏輯正確。匯入時重新計算完整性，不信任外部檔案宣稱的完成狀態。

## 6. 主題與轉場

- 提供淺色／深色切換按鈕，保存偏好，下次開啟沿用。
- 子圖畫布切換、節點設定面板與確認視窗加入短動畫銜接。
- 遵循作業系統的「減少動態效果」設定，關閉非必要動畫。

## 7. 開發依據與實作分層

使用者要求系統描述盡可能精細、清楚，以減少 Agent 推測。設計須能表達前置條件、完成條件、資料限制與範例、連線資料對應及分支條件；以分區和進階設定維持介面易用性。

遵循專案根目錄的 AI 協作規範與 SKILLS/frontend：資料模型先於業務邏輯、元件責任分離、資料來源一致、外部輸入驗證、錯誤可恢復，以及明確的操作狀態回饋。

- `src/domain`：文件型別、Schema、圖操作與結構／完整性驗證。
- `src/useEditor.ts`：唯一專案狀態、50 步記憶體復原與重做、自動暫存。
- `src/components`：React Flow 畫布、節點／返回線設定、Schema 表單與對話框。
- `src/persistence.ts`：瀏覽器草稿、JSON 讀取與本地下載。
- 無後端、執行引擎或程式碼生成服務。

## 8. 操作邊界與恢復

- 草稿使用 localStorage，修改後延遲 700ms 寫入；離開／切換至背景時再嘗試寫入。額度不足時顯示匯出建議，不宣稱已保存。
- 原草稿無法解析時保留原內容並停用自動覆寫，手動確認後才重新啟用。
- 復原／重做保留當前工作階段最近 50 步完整快照；重新載入後不保留歷史。
- 匯入檔案上限 10 MB，以避免一次載入過量資料阻塞畫面。
- 清空子圖會連同邊界 items 一起清除；父節點及子圖引用保留，完整性檢查標示缺少邊界。可復原或在專案設定重建邊界。
- 父節點連接埠 ID 對應子圖入口／出口；更新契約同步子圖。移除連接埠會移除相关連線並可復原。
- 本版不保證多分頁同時編輯合併，也不實作多人同步；以單一編輯分頁工作。
- 進階 Schema 的原始文字需按「套用 Schema」才成為文件內容；無效輸入不覆蓋已套用的契約。
- 存在未套用的進階 Schema 時阻擋切換項目及匯出，提供「套用」與「放棄未套用變更」，避免静默遺失。
